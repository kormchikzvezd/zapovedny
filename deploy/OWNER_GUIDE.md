# Как управлять домами — одна страница

Дома перечислены в файле `catalog/homes.json`. На сайте видны только дома
со статусом `available`. Остальные скрыты, и заявку на них сервер не примет.

## Статусы

| Статус | Что значит | Виден на сайте |
| --- | --- | --- |
| `available` | Дом в продаже | Да |
| `reserved` | Забронирован, ждём сделку | Нет |
| `sold` | Продан | Нет |
| `preparing` | Готовится к продаже | Нет |

## Команды

Все команды выполняются в папке проекта на сервере.

### Посмотреть текущее состояние

```bash
npm run homes -- list
```

### Дом продали или забронировали

```bash
npm run homes -- status 8/1 sold
npm run homes -- status 8/1 reserved
```

### Дом вернулся в продажу

```bash
npm run homes -- status 8/1 available
```

### Добавить новый адрес

Новый дом сначала добавляют как `preparing`, и только после проверки
переводят в `available`:

```bash
npm run homes -- add 9/1 standard "https://2gis.ru/tomsk/search/Казачья%20улица%209%2F1"
```

Планировки: `standard` — 3 спальни, `extra-room` — 3 спальни и комната на первом этаже,
`confirm` — планировка уточняется.

### Опубликовать изменение

```bash
npm run homes:check     # проверка: дубликаты, названия, статусы, ссылки 2ГИС
npm run build           # пересборка сайта с новым каталогом
sudo systemctl restart zapovedny
```

**Порядок важен.** Без `npm run build` сайт продолжит показывать старый состав домов:
каталог вшивается в сборку на этапе `build`.

## Если проверка ругнулась

`npm run homes:check` останавливает работу при настоящей ошибке — это защита,
а не поломка. Типичные сообщения:

| Сообщение | Причина |
| --- | --- |
| `Повторяется адрес 8/1` | Добавлен адрес, который уже есть |
| `Проверьте название дома 9/1` | Название должно быть ровно `Казачья, 9/1` |
| `Неизвестный статус` | Статус не из четырёх перечисленных |
| `Проверьте ссылку 2ГИС` | Ссылка должна начинаться с `https://2gis.ru/tomsk/` |

## Посмотреть заявки

```bash
sqlite3 /opt/zapovedny/data/leads.db \
  "select created_at, name, phone, preferred_channel, homes from leads order by id desc limit 20;"
```

## Откатить сайт, если что-то сломалось

```bash
cd /opt/zapovedny/app
git log --oneline -5
git checkout <предыдущий-коммит>
npm ci && npm run build
sudo systemctl restart zapovedny
```

Заявки при этом сохраняются: структура базы не меняется.

## Секреты — не в git

Токен Telegram и ключи хранятся в `/opt/zapovedny/app/.env` с правами 600.
В репозитории их быть не должно. Проверить перед коммитом:

```bash
git status --short
grep -rn "TELEGRAM_BOT_TOKEN=" --include="*.env*" . || echo "секретов в коде нет"
```
