# Управление домами на Казачьей

Единственный список адресов — `catalog/homes.json`. Сайт, сравнение домов, число домов в продаже и проверка заявок используют его. В открытой продаже показываются **только** записи со статусом `available`. Проданные записи остаются в файле для истории, но исчезают из списка под картой, карточки, сравнения и выбора в заявке. Сама подложка 2ГИС показывает всю улицу и не является схемой наличия.

## Статусы

| Статус | Когда ставить | На сайте |
| --- | --- | --- |
| `preparing` | Строится, оформляется или ещё не проверен для продажи | Скрыт |
| `available` | Готов к продаже; адрес, документы и возможность показа подтверждены | Показан |
| `reserved` | Бронь подтверждена | Скрыт |
| `sold` | Продажа завершена | Скрыт |

## Команды из корня проекта

```bash
npm run homes -- list
npm run homes -- status 5/1 reserved
npm run homes -- status 5/1 sold
npm run homes -- add 9/1 standard 'https://2gis.ru/tomsk/geo/ПРОВЕРЕННАЯ_ССЫЛКА'
npm run homes -- status 9/1 available
npm run homes:check
npm run build && npm test
```

`add` всегда создаёт адрес со статусом `preparing`, поэтому он не появится раньше проверки. Для обычного дуплекса планировка `standard`, для дома с дополнительной комнатой на первом этаже — `extra-room`, для ещё не подтверждённой планировки — `confirm`. Ссылку 2ГИС нужно проверить вручную. Команда `status` меняет запись в файле; на опубликованном сайте изменения появятся после новой сборки и публикации версии.

## Рабочий порядок

1. Ответственный за продажи подтверждает факт брони/продажи или готовность нового дома к открытой продаже. Не ставьте `available` только по факту начала строительства.
2. Обновите статус существующего адреса или добавьте новый. Для нового адреса проверьте номер, планировку, фото и ссылку 2ГИС, затем смените `preparing` на `available`.
3. Запустите проверку каталога, сборку и тесты. Посмотрите опубликованную страницу: список под картой, выбранный дом, сравнение и форму заявки. Также проверьте текущие цену, общие характеристики и рекламный текст: они относятся ко всему сайту и могут потребовать отдельной правки для новой очереди.
4. Опубликуйте новую версию сайта. При продаже делайте это сразу после подтверждения статуса; до публикации прежняя версия продолжает показывать адрес.

Для переноса на другую платформу экспортируйте этот JSON как каталог. Там следует подключить его к закрытой редакторской форме с авторизацией, историей изменений и публикацией после проверки. Публичная часть должна использовать то же правило `status === 'available'`; форма заявки должна проверять тот же актуальный набор адресов на сервере. Перенос заявки и базы лидов — отдельная часть миграции, её нельзя подменить одним переносом каталога.
